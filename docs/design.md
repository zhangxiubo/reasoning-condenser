# Design

## Objective

Reduce future prompt consumption by replacing exposed historical reasoning before a coding agent stores it.

The design optimizes retained context. It does not attempt to reduce reasoning generated by the primary model during the current turn.

## Modules

```text
server
  └── reasoning_router
        ├── anthropic_request
        ├── openai_request
        ├── openai_client
        ├── normalized_turn
        ├── archive
        ├── condensation
        │     └── token_estimator
        ├── anthropic_response
        └── openai_response
```

`NormalizedTurn` is the boundary between client protocol details and condensation policy. It contains separated reasoning, final text, parsed tool calls, stop reason, model identity, and actual upstream usage. The Anthropic and OpenAI serializers both consume this same value.

## Primary-response contract

The primary adapter accepts either:

- `message.reasoning_content`, `message.reasoning`, or `message.thinking`; or
- A leading `<think>...</think>` block inside `message.content`.

Separated reasoning takes precedence. Inline extraction is only a compatibility fallback.

Tool argument text must parse to a JSON object. Invalid or non-object arguments are rejected because rewriting them would change behavior.

## Condensation policies

Policy selection is data-driven by the normalized turn shape:

| Turn shape | Policy | Intent |
|---|---|---|
| No tool calls | `completed_response` | Remove state already represented by the final response |
| One or more tool calls | `tool_continuation` | Retain the immediate plan and evidence needed after tool execution |

Each policy has an independent replacement-size maximum and target ratio. Reasoning below the common minimum passes through. The condenser's separate generation allowance covers both its own reasoning and its final JSON, so enabling condenser thinking does not reduce the requested replacement size.

The condenser receives only the current turn's original reasoning, final response, exact normalized tool calls, and policy instruction. It returns a JSON object containing replacement reasoning. Tool calls remain outside the generated field.

## State transitions

```text
received
  → primary_completed
  → normalized
  → archived_or_archive_skipped
  → condensed | passed_through
  → serialized
  → delivered
```

The original normalized turn is never mutated. Successful condensation creates a new turn value with replacement reasoning. All failure outcomes retain the original value.

## Usage accounting

Two measurements are intentionally retained:

- Upstream usage reports primary-model computation.
- Visible usage estimates the response the coding agent stores.

The response body uses visible output usage so client-side context management reflects the delivered content. Structured logs and `x-rcr-upstream-*` headers retain the actual upstream counts.

The visible estimate uses configurable characters per token. Exact tokenization is a possible future provider adapter, but it should use the primary endpoint's tokenizer service or matching tokenizer data rather than an unrelated generic tokenizer.

## Failure policy

Condensation is an optional transformation. Its failures return the original successful primary response.

Primary endpoint failures and malformed primary tool calls are request failures. They cannot safely be converted into a successful assistant response.

Archival failures are logged and do not affect delivery.

## Streaming

No primary content is sent before condensation completes. Upstream requests therefore set `stream=false`.

For downstream Anthropic streaming requests, the serializer emits events in this order:

1. `message_start`
2. Thinking block events, including a local content-derived signature
3. Text block events
4. Tool-use block events
5. `message_delta`
6. `message_stop`

The local signature provides stable protocol-shaped data for Claude Code. It is not an Anthropic signature and is never validated upstream.

For OpenAI streaming requests, the serializer emits a reasoning chunk, final-content and tool-call chunks, a finish chunk, an optional usage-only chunk, and `[DONE]`. Both streaming paths begin only after condensation has completed.

## Security boundary

Both primary and condenser endpoints can receive sensitive coding-session data. They should be treated as part of the same trust boundary.

Original-turn archival is disabled unless a path is configured. Request and response content is not written to normal logs.
